## 3. 已批准的真实分享产品规则（D-052）

- Receiver 无需登录或密码。公开查看地址使用不可猜测的随机标识；任何拿到链接的人仍可能查看和转发，所以 `noindex` 只降低被搜索引擎发现的概率，不等于访问控制。
- Receiver 查看链接与 Sender 管理入口完全分开。管理凭证不得进入 Receiver URL、Receiver 数据、分享文案、错误信息、分析事件或服务器访问日志。
- 默认有效期为发布后一年；Sender 可以提前撤回。到期、撤回及已完成删除的 Receiver 页面统一显示“这份惊喜已经收起来了”，不回落到 Mia Demo，也不暴露内部状态差异。
- 每次发布生成不可变快照。Sender 修改草稿后再次发布会生成新链接；确认新链接可正常打开后，Sender 再主动撤回旧链接。旧链接不自动跳转到新版本。
- 产品只保存 Ta-da! 内容与外部礼物 URL；不读取或保存电商账号、Cookie、地址、订单、付款、验证码或物流信息。淘宝 / 京东 / 微信小店只是外部入口，不由 Ta-da! 声称领取、付款或送达成功。

## 4. 实现方案与安全边界（D-052 / D-053 已冻结，云资源待选）

### 数据与职责

- 保留现有 `SurpriseContent` 的游戏、Card / Scrapbook 二选一、照片顺序 / 裁切、可选礼物结构。新增发布记录与资源记录，不让业务组件各自读取数据库。
- 发布记录包含内部 id、公开的随机查阅标识哈希、内容 schemaVersion、状态、创建时间、一年到期时间、撤回时间、删除时间，以及服务端管理归属。公开标识至少使用 128 位安全随机值；数据库只存哈希，不把原值写入日志。
- P0 不增加账号登录。00 推荐首次发布由服务端设置 `HttpOnly`、`Secure`、`SameSite=Lax` 的 Sender 管理会话 Cookie，数据库只保存管理密钥哈希；管理路由与 Receiver 路由分开，所有撤回操作同时校验管理会话、资源归属和请求来源。清除浏览器数据或更换设备后默认无法恢复管理权，不在 Receiver 链接中塞恢复凭证绕过。该“仅原浏览器可管理、P0 不提供找回”属于待用户随实施包确认的技术默认，不属于 D-052 已批准产品规则。
- 照片进入私有对象存储，发布快照只保存资源 id、尺寸、顺序和原始裁切参数；浏览器本地 blob URL 不能作为远程作品资源，照片也不能塞进分享 URL。Receiver 数据加载成功后由服务端生成最多 10 分钟的短时读取地址。撤回或到期后不再签发新地址；已签发地址可能在到期前继续有效，因此短时有效期属于撤回生效边界。[Supabase 私有存储与短时链接](https://supabase.com/docs/guides/storage/buckets/fundamentals)
- 上传应校验实际文件格式、大小与数量；重编码并去除 EXIF 等不必要元数据，防止照片携带位置；明确像素与清晰度上限，保留裁切效果。文件名由服务端生成，不直接沿用用户输入。[文件上传安全参考](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- 公共查阅标识使用安全随机生成、不可预测的值；建议至少 128 位随机性。查阅权和管理权分离，查阅限流；服务端固定可信分享域名，不使用任意请求 Host 拼链接。此处借鉴 URL token 的随机性与防泄露原则，不照搬密码重置的“一次使用即失效”。[URL token 原则参考](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)

### 发布顺序

```text
保留本地草稿 → 校验内容 → 上传照片并确认归属
           → 服务端原子保存可读取的内容版本 → 返回唯一链接
           → 复制 / 分享 → 新设备读取同一个版本
```

- 上传全部完成后才能发布成功；失败保留草稿并可重试。连续点击或网络重试应使用幂等标识，不重复创建作品；默认常量 draftId 不能直接当幂等 id 或公共 id。
- 不存在、读取失败、到期、撤回应有明确可恢复 / 不可恢复状态；不回落成 Mia Demo 冒充成功。
- 保留 `mia-birthday` 作为固定演示入口，与用户作品数据分开。Receiver 由路由层加载并校验后传给现有壳层；不把数据库访问塞进 Gift / Card / Scrapbook。
- 更新 / 撤回必须校验创建者权限。缓存、图片授权有效期和撤回生效时间共同设计；分享预览固定使用 Ta-da! 通用标题与品牌图，不泄露双方姓名、私人祝福或用户照片。
- 禁止把令牌、私人照片或完整礼物领取链接放进日志 / 埋点；页面禁止索引只能降低被发现机会，不能替代访问控制。

### 最小数据与资源模型

| 对象 | 最小字段与规则 |
|---|---|
| `sender_sessions` | `id`、`secret_hash`、`created_at`、`last_seen_at`、`expires_at`；只由服务端 Cookie 关联，不能出现在 Receiver 数据中 |
| `surprises` | `id`、`public_token_hash`、`owner_session_id`、`schema_version`、`payload_json`、`status`、`published_at`、`expires_at`、`revoked_at`、`deleted_at`；每次发布新建，不原地改内容 |
| `media_assets` | `id`、`surprise_id`、`object_key`、`mime_type`、`bytes`、`width`、`height`、`status`、`created_at`、`deleted_at`；对象名由服务端生成，Bucket 保持私有 |
| `publish_operations` | `idempotency_key`、`owner_session_id`、`status`、`surprise_id`、`created_at`、`expires_at`；重复点击或网络重试返回同一发布结果 |

发布事务采用“先校验 → 创建幂等发布操作 → 上传并验证资源 → 原子写入不可变快照 → 返回查看链接”。任一步失败都保留本地草稿和可重试状态；未完成资源不进入公开快照，并由清理任务回收。

### 失效、删除与状态

- `active`：Receiver 可读取；`expired` / `revoked` / `deleted`：Receiver 统一显示“这份惊喜已经收起来了”；`publishing` / `failed` 只在 Sender 侧显示。
- 到期或撤回立即禁止新的内容读取与照片签名，不提供 Receiver 恢复入口。00 推荐内容、管理关系和照片进入删除队列，并在 7 天内完成硬删除；该 7 天只用于后台重试和核对，不提供用户可见撤销。删除时限属于待用户随实施包确认的技术默认，不属于 D-052 已批准产品规则。
- 找不到、格式非法或服务不可用不得回退成固定 Demo。服务暂时不可用显示可重试错误；已撤回 / 到期使用已批准终态文案。

## 5. 外部礼物链接：先验证边界，再承诺支持

当前 `getGiftLinkPlatform` 仅检查 HTTPS 并按域名分组；任意 HTTPS 可归为“礼物链接”，`weixin.qq.com` 被统一归为“微信小店”。这只能说明地址形式和域名，不能证明页面是官方赠礼入口，更不能证明无订单 / 地址 / 登录信息泄露。

现有卡片已有 `target="_blank"`、`rel="noreferrer noopener"`，后续保留。底部“收好礼物”只推进 Ta-da! 流程，不代表电商已领取、已支付或已送达。

建议统一的前后端校验（待实现）：

- 拒绝非 HTTPS、带 username/password 的 URL、控制字符、明显本地 / 内网目标；使用解析后的完整主机名，防止 `taobao.com.evil.example` 等相似域名。
- 官方域名与“可领取链接”的业务识别分开。未知入口可显示真实域名并提示未验证，但保留还是拒绝需 05 决定；不擅自把所有微信域名标成微信小店。
- 领取参数可能就是领取凭证，不自动剥离所有 query，也不将原链接发送到第三方“安全检测”站。拒绝登录态导出、Cookie、验证码、个人订单详情等内容；仅依靠参数黑名单仍无法保证安全。
- 默认不在服务器抓取任意用户网址或自动跟随短链；如果以后确需解析短链，应限制目的地址、每次重定向、DNS / 内网访问，并隔离网络权限，避免 SSRF。[SSRF 防护参考](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
- 平台自身是否要求登录、能否唤起 App、链接过期或被风控，是独立于 Ta-da! 的状态；不能保证微信内网页都能直接打开。

### 必须安排的验证矩阵

| 样本 | 环境 | 记录与边界 |
|---|---|---|
| 淘宝 / 京东 / 微信小店官方赠礼或领取入口 | iPhone Safari、Android Chrome、iOS / Android 微信内浏览器 | 打开结果、跳转目标域、是否要登录 / App、是否显示私人订单或地址；不输入真实地址、不提交领取 / 付款 |
