# 回忆手帐编辑交互审查

**日期：** 2026-09-11  
**产品面：** Sender 第 3 / 5 步「回忆手帐」  
**预览：** `http://127.0.0.1:3003/create`  
**结论：** 视觉成熟，照片裁切也可用；主要问题是「选版式—补照片—调画面—完成」被拆成了多个信息区，而缺照片时使用事后报错，让用户需要来回判断下一步。

## 流程步骤

1. **手帐主页—基本可用，信息偏重**  
   证据：`/tmp/tada-scrapbook-audit/01-scrapbook-main.jpg`  
   用户同时看到当前版式、照片状态、替换说明、实时预览和调整说明。功能都有，但下一个动作不够聚焦。

2. **照片调整—健康**  
   证据：`/tmp/tada-scrapbook-audit/02-photo-adjust.jpg`  
   裁切预览、缩放、重置、替换和完成的结构清楚。建议只把图片上的「拖动照片」说明移到图片下方，避免遮住画面。

3. **版式选择—可用，确认逻辑不一致**  
   证据：`/tmp/tada-scrapbook-audit/03-layout-picker.jpg`  
   版式是互斥选择，但语义上使用 checkbox；点击需更多照片的版式会立即应用并关闭弹层，而减少照片的版式又有二次确认。建议统一为 radio 选择，底部用「使用这个版式」确认。

4. **换版式后缺照片—需优化**  
   证据：`/tmp/tada-scrapbook-audit/04-layout-changed-missing-photo.jpg`  
   页面已能显示「还差 1 张」，但底部仍显示「完成心意」且可点，用户容易先点完成再被告知错误。

5. **缺照片校验—可恢复，但反馈重复**  
   证据：`/tmp/tada-scrapbook-audit/05-missing-photo-validation.jpg`  
   点击「完成心意」后，页面顶部出现错误卡，照片区又出现一次相同说明。问题能被发现，但需要用户自己再定位「选择照片」。

## 最高优先级优化

### 1. 让底部主按钮跟当前任务变化

- 缺 1 张时：按钮改为「再选 1 张照片」，点击直接打开选图。
- 照片齐全时：按钮恢复「完成手帐」。
- 删除顶部大错误卡，仅在空照片位附近给一处明确提示。

### 2. 把「选图」和「调整」收到预览本身

- 空照片位：显示「+ 添加照片」。
- 已有照片：右下角显示小操作「调整」。
- 点击预览里的照片就进入裁切弹层，不再另设「照片 / 实时预览」两块重复说明。

### 3. 版式选择加一个稳定的确认步骤

- 点选卡片只更新弹层里的选中态。
- 底部固定「使用这个版式」。
- 只在会删除已有照片时，补一句就地警告，不再打开第二层弹窗。

## 建议的新页面顺序

1. 页面标题＋一句说明。
2. 当前版式卡，可更换。
3. 一张可直接操作的实时预览：空位添加，已填照片调整。
4. 共同说明（可选）。
5. 根据照片完整度变化的底部主按钮。

## 可访问性与证据边界

- 版式选择建议使用 radio 语义而非 checkbox。
- 照片热区已有可读的「调整第 N 张照片」名称，这点保留。
- 本次核对了可见结构、按钮状态、版式切换、裁切弹层和缺图校验；未代替真实屏幕阅读器与触屏设备测试。
